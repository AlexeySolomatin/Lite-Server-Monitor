# Инструкция по коммитам и версионированию LSM

В проекте **Lite Server Monitor (LSM)** настроено автоматическое версионирование. Название каждого коммита определяет, как GitHub Actions обновит версию в файле `VERSION` и создаст новый Git-тег.

Скрипт проверяет историю изменений от последнего тега до текущего момента.

---

## 📌 Таблица типов коммитов

| Префикс / Текст | Описание | Результат версионирования | Пример сообщения |
|---|---|---|---|
| **Любой текст** (или `fix:`, `docs:`, `chore:`) | Мелкие правки, исправление ошибок, документация | **PATCH** (`0.1.3` → `0.1.4`) | `fix: исправил падение logging.sh` <br> *или просто:* `обновил ридми` |
| **`feat:`** *(строго маленькими буквами)* | Новая функция или модуль в начале коммита | **MINOR** (`0.1.3` → `0.2.0`) | `feat: добавил модуль мониторинга Docker` |
| **`!:`** или **`BREAKING CHANGE`** | Критическое / ломающее изменение (в любом месте сообщения) | **MAJOR** (`0.1.3` → `1.0.0`) | `feat!: переработка структуры конфигурации` <br> *или:* `fix!: изменен формат логов` |

---

## 💻 1. Как делать коммиты из консоли (на сервере / локально)

### Однострочный коммит (Основной способ)

```bash
# Для обычного исправления бага (увеличит PATCH)
git add .
git commit -m "fix: исправил ошибку unbound variable в logging.sh"
git push origin main
```

### Для добавления новой фичи (увеличит MINOR)

```bash
# Префикс feat: обязательно должен быть в самом начале и маленькими буквами
git add .
git commit -m "feat: добавил проверку системных служб"
git push origin main
```

---

### Подробный коммит с несколькими строками

Если нужно описать подробности, используйте несколько флагов `-m`. Если внутри текста будет фраза `BREAKING CHANGE`, версия обновится до **MAJOR**:

```bash
git commit -m "feat: добавил модуль docker" -m "BREAKING CHANGE: изменен путь к файлу конфигурации lsm.conf"
```

## 2. Как делать коммиты через веб-интерфейс GitHub
1. Откройте нужный файл в браузере на GitHub и нажмите иконку **Редактировать (карандаш)**.
2. Внесите изменения в код.
3. В правом верхнем углу нажмите синюю кнопку **Commit changes...**.
4. В поле **Commit message** введите заголовок с префиксом (например, `feat: добавил tui интерфейс`).
5. В поле **Extended description** (необязательно) добавьте подробное описание.
6. Нажмите **Commit changes**.

## ⚙️ Как работает автоматика

1. После выполнения `git push` (или сохранения файла на сайте) автоматически запускается GitHub Actions.
2. Скрипт `lib/installer/auto-version.sh` анализирует накопленную историю коммитов со времени последнего релиза.
3. Файл `VERSION` автоматически перезаписывается на новый номер.
4. Этот же номер автоматически подставляется в ваш `README.md` (в бейдж версии и текстовый маркер).
5. В репозитории автоматически создается соответствующий Git-тег (например, `v0.1.4`).
