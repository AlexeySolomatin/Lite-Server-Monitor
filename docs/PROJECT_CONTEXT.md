### 1. PROJECT IDENTITY
---

Название:

    Lite Server Monitor (LSM)


Назначение:

    Легковесная модульная система мониторинга Linux-серверов
    с уведомлениями и автоматическими проверками.


Цель:

    SMB / small infrastructure monitoring.

    Приоритеты:

        1. Надежность
        2. Простота сопровождения
        3. Предсказуемость поведения
        4. Минимум зависимостей
        5. Модульность


LSM НЕ является:

    - enterprise monitoring системой;
    - заменой Zabbix/Prometheus;
    - агентом с тяжелой инфраструктурой.


---
### 2. ARCHITECTURE PRINCIPLES
---

Основные принципы:

1. Простота важнее моды.

2. Bash выбран намеренно:
   
   Причины:
       - доступен на любом Linux сервере;
       - минимальные зависимости;
       - легко диагностировать;
       - легко восстановить вручную.


3. Каждый модуль автономен.

4. Модуль отвечает только за свою проверку.

5. Уведомления централизованы.

6. Конфигурация отделена от кода.

7. State-файлы используются для хранения состояния.

### 7. MODULE EXECUTION MODEL
---


Модули работают через systemd timers.


Пример:


lsm-disk.timer

        |

        v

lsm-disk.service

        |

        v

check_disk.sh



Каждая проверка:

    1. Загружает конфигурацию.
    2. Выполняет проверку.
    3. Определяет состояние.
    4. Вызывает notify().
    5. Обновляет state.


---
### 8. STATE MODEL
---


Каталог:


/var/lib/lsm/state/


Назначение:

    Хранение текущего состояния проблем.


Формат:


module.state


Пример:

disk.state


Используется для:

    - защиты от повторных уведомлений;
    - определения восстановления.

9. NOTIFICATION API
===============================================================================


Главный файл:


lib/notifications/notify.sh


Основная функция:


notify module level message


Пример:


notify \
    "disk" \
    "CRITICAL" \
    "Раздел заполнен"



Уровни:


OK

    восстановление


WARNING

    предупреждение


CRITICAL

    критическая проблема



Логика:

    - throttling;
    - recovery;
    - escalation WARNING -> CRITICAL.

14. IMPORTANT DESIGN CONTRACTS
===============================================================================


НЕ делать:

- смешивать UI и бизнес-логику;
- отправлять уведомления напрямую из модулей;
- создавать новые форматы state без необходимости;
- дублировать функции core библиотек.


Делать:

- использовать logging API;
- использовать notify API;
- использовать module structure;
- хранить конфиги отдельно.

15. CURRENT KNOWN ISSUES
===============================================================================


В процессе разработки были обнаружены:

1.

Несогласованность цветовых переменных:

старый вариант:

    CLR_RED
    CLR_RESET


новый вариант:

    COLOR_RED
    COLOR_RESET


Решение:

    Все новые компоненты используют COLOR_*.


2.

Installer требует проверки совместимости:

    ui.sh
    colors.sh
    installer/screens/*


3.

Необходимо поддерживать единый API библиотек.
