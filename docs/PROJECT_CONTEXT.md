----------------------------------------------------------
### 1. PROJECT IDENTITY
----------------------------------------------------------

Название:

    Lite Server Monitor (LSM)


Назначение:

    Легковесная модульная система мониторинга Linux-серверов
    с автоматическими проверками и уведомлениями.

Цель:

    SMB / small infrastructure monitoring.

Приоритеты:

        1. Надежность
        2. Простота сопровождения
        3. Предсказуемость поведения
        4. Минимум зависимостей
        5. Модульность


 LSM НЕ является:

    - enterprise monitoring системой;
    - заменой Zabbix;
    - заменой Prometheus;
    - тяжелой распределенной системой мониторинга;
    - агентом, требующим сложной серверной инфраструктуры.


----------------------------------------------------------
### 2. ARCHITECTURE PRINCIPLES
----------------------------------------------------------

Основные архитектурные принципы:

1. Простота важнее моды.

2. Bash выбран намеренно.

   Причины:

       - доступен практически на любом Linux-сервере;
       - минимальное количество зависимостей;
       - легко диагностировать;
       - легко восстановить вручную;
       - удобно использовать системные инструменты Linux.

3. Компоненты должны иметь четкую ответственность.

4. Каждый мониторинговый модуль отвечает только
   за собственную область проверки.

5. Уведомления должны быть централизованы.

6. Конфигурация отделена от кода.

7. Состояние системы хранится отдельно от исходного кода.

8. Существующие API должны переиспользоваться,
   а новые API создаются только при необходимости.

9. Не следует усложнять архитектуру без практической необходимости.

### 7. MODULE EXECUTION MODEL
----------------------------------------------------------


Модули работают через systemd timers.


Пример:


lsm-disk.timer

        |

        v

lsm-disk.service

        |

        v

check_disk.sh



Каждая проверка:

    1. Загружает конфигурацию.
    2. Выполняет проверку.
    3. Определяет состояние.
    4. Вызывает notify().
    5. Обновляет state.


----------------------------------------------------------

### 9. NOTIFICATION API
----------------------------------------------------------


Главный файл:


lib/notifications/notify.sh


Основная функция:


notify module level message


Пример:


notify \
    "disk" \
    "CRITICAL" \
    "Раздел заполнен"



Уровни:


OK

    восстановление


WARNING

    предупреждение


CRITICAL

    критическая проблема



Логика:

    - throttling;
    - recovery;
    - escalation WARNING -> CRITICAL.

### 12. INTERNAL API CONTRACTS
----------------------------------------------------------


Logging API:

All components use:

    log_info COMPONENT MESSAGE
    log_success COMPONENT MESSAGE
    log_warn COMPONENT MESSAGE
    log_error COMPONENT MESSAGE

Provided by:

    lib/core/logging.sh


--------------------------------------------------


UI Color API:

Legacy compatibility variables:

    CLR_RESET
    CLR_BOLD
    CLR_RED
    CLR_GREEN
    CLR_YELLOW
    CLR_CYAN

Provided by:

    lib/core/ui.sh

Internal color provider:

    lib/core/colors.sh
    
--------------------------------------------------

LSM_ROOT Variable Contract:

Глобальный корень LSM.

CLI после установки:

    /opt/lsm

Во время установки:

    Путь к текущему дереву проекта.

Правила:

    - экспортируется;
    - НЕ объявляется readonly;
    - библиотеки могут использовать конструкцию ${LSM_ROOT:-...};
    - дочерние скрипты наследуют LSM_ROOT через environment.

--------------------------------------------------

UNINSTALL CONTRACT:

- installer/uninstall.sh loads installer libraries for orchestration.
- modules/*/uninstall.sh are executed in separate Bash processes.
- Every module uninstall script MUST load its own required libraries.
- deploy.sh provides:
  - deploy_create_directory
  - deploy_install_file
  - deploy_create_symlink
  - deploy_remove_file
  - deploy_remove_directory

Необходимо поддерживать единый API библиотек.
