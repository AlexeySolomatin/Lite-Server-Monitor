# Lite Server Monitor (LSM)

## Аудит проекта и план развития

Версия документа: 1.0

Дата: август 2026

Базовая версия кода: 0.1.229+

---

# 1. Назначение документа

Документ фиксирует результаты полного технического аудита проекта,
перечень выполненных исправлений и рекомендации по улучшению
и дальнейшему развитию.

Аудит охватил:

- все 10 модулей каталога `modules/`;
- CLI (`bin/lsm`, `commands/`);
- установщик (`installer/`, включая steps и screens);
- библиотеки (`lib/core`, `lib/installer`, `lib/notifications`);
- конфигурационные шаблоны (`templates/`);
- документацию.

## 2.2. Дефекты согласованности (исправлены)

- Плоские копии check-скриптов в корнях каталогов модулей (disk, docker,
  fail2ban, login, raid, smart, system, temperature, ups) — мертвый груз,
  вводивший в заблуждение документацию. Удалены.
- uninstall-скрипты модулей не удаляли конфиги и state-артефакты;
  часть библиотек подключалась безусловно и могла обрывать удаление.
  Приведены к симметричной полной очистке с условными source.
- disk использовал собственную пару корней LSM_ROOT/LSM_INSTALL_DIR.
- system: manifest содержал описание от другого модуля.
- Мертвые опции конфигураций реализованы либо задокументированы:
  MONITOR_JAILS (fail2ban), REPORT_TEMPERATURE и NOTIFY_ON_* (smart),
  NOTIFY_ON_WARNING/NOTIFY_ON_RECOVERY (system), RUNTIME_WARNING (ups).
- Установщик дважды создавал symlink `/usr/local/bin/lsm`.
- installer/steps/02_packages.sh ссылался на чужую константу компонента.
- commands/config.sh падал при отсутствии /etc/lsm.
- Опечатка с кириллической буквой в комментарии permissions.sh.
- templates/{notifications,modules,thresholds}.conf и
  lib/installer/config_builder.sh — мертвые артефакты удалены.
- templates/config.conf и secrets.conf актуализированы и русифицированы.

## 2.3. Русификация и унификация (выполнено)

- Все пользовательские сообщения и комментарии приведены к русскому языку.
- Шапки всех скриптов унифицированы по эталону installer/install.sh:
  рамки `# ===...===`, секции «Путь:» и «Назначение:», русские заголовки.
- README.md каждого модуля переписан по единому шаблону
  (назначение, принцип работы, все параметры конфигурации, файлы,
  ручной запуск, требования).

# 3. Текущее состояние

## 3.1. Что работает

- Полный цикл установки/обновления/удаления через bootstrap + wizard.
- Все 10 модулей соответствуют контракту Module API.
- Централизованные уведомления Telegram + Email (msmtp) с throttling,
  эскалацией и recovery.
- Ежедневный сводный отчет (`core` → lsm-report.timer).
- Диагностика `lsm doctor` с различением системных и мониторинговых модулей.
- Управление модулями через `lsm modules ...` (включение = systemd timer).

## 3.2. Ограничения текущей версии

- Автотесты отсутствуют; проверки выполнялись смоук-тестами в песочнице
  и ревью кода. RAID/DISK-ветки на реальном железе не прогонялись.
- doctor считает любой WARNING модуля (exit 1) ошибкой диагностики —
  гранулярность отчета ограничена.
- Часть сообщений об ошибках systemd-юнитов может быть скрыта
  sandbox-ограничениями (ProtectSystem=strict) — требуется живая проверка.

# 4. Рекомендации по улучшению

Приоритет P0 (сделать перед 1.0):

1. **Живое тестирование на чистой VM** (Ubuntu 22.04/24.04, Debian 12):
   полный цикл install → configure → 24 часа работы → update → uninstall.
   Проверить доставку уведомлений каждого уровня и daily report.
2. **Тестовый каркас**: минимальный `tests/` со smoke-прогоном
   check-скриптов всех модулей в mock-окружении (фейковые smartctl,
   apcaccess, docker, fail2ban-client). Запуск в CI (GitHub Actions).
3. **shellcheck в CI**: workflow уже есть — убедиться, что он зеленый
   после волны изменений, включить строгий профиль для новых файлов.
4. **Doctor v2**: разделить итог на ошибки/предупреждения с учетом
   exit 1 модулей как warning, а не error; добавить проверку
   конфигурации уведомлений (валидность TELEGRAM_*, SMTP_*).
5. **Идемпотентность обновлений**: перезапись /etc/lsm/config.conf
   шаблоном при повторной установке исправлена в ходе аудита
   (шаблон копируется только при первом создании файла).
   Требуется живая проверка сценария «обновление поверх настроенной
   системы».

Приоритет P1 (ближайшее развитие):

6. **Единый источник правды по путям**: вынести /opt/lsm, /etc/lsm и т.д.
   в один lib/core/paths.sh вместо рассыпанных дефолтов.
7. **Унифицировать компоненты логирования модулей** (DISK, SMART...)
   в одну константу из манифеста.
8. **Проверка конфигурации**: `lsm config validate` — синтаксическая
   проверка всех .conf до перезапуска сервисов.
9. **Модульные таймауты**: добавить TimeoutStartSec в service-юниты,
   чтобы зависший check не блокировал очередь systemd.
10. **Метрики производительности**: длительность каждой проверки
    в логе (для выявления медленных модулей).

Приоритет P2 (долгосрочно):

11. **TUI**: полноценный интерактивный интерфейс. Частично
    реализовано в ходе аудита: мастер установки получил
    интерактивный чек-лист выбора модулей (wizard_checklist,
    переключение [ ]/[X] цифрами, подтверждение по 0).
12. **Экспорт метрик**: необязательный textfile-экспортер для node_exporter
    без нарушения принципа легковесности.
13. **Расширение ОС**: Rocky/Alma/RHEL после стабилизации Debian-семейства.
14. **Локализация en**: вынести строки сообщений в отдельный слой i18n,
    если проект пойдет к международной аудитории.

# 6. Итог

Проект прошел путь от прототипа с разрозненными стандартами
к согласованной модульной системе: единый контракт модулей,
единый канал уведомлений, единый стиль кода и документации.

Ключевое условие выхода на 1.0 — живая валидация (P0-1)
и тестовый каркас (P0-2), защищающий от регрессий.
